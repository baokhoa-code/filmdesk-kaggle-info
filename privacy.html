Privacy Policy

This policy covers the FilmDesk Kaggle Google Drive connection and its notebook workflow, operated by baokhoa-code for personal use.

Data accessed

The connection accesses files and metadata in the owner's configured input, output and log folders. These may include episode videos and audio, thumbnails, titles, descriptions, source URLs, file IDs, sizes, checksums, processing results and recovery checkpoints. OAuth credentials are used to access Drive on the owner's behalf. The workflow does not require the owner's Google password.

The requested Drive scope permits account-wide file access at the API level. The application uses configured folder IDs to restrict its operations; those IDs are an application-level limit, not a Google-enforced restriction on the token.

Purpose and processing

Data is used to validate inputs, process video and audio in a user-run Kaggle session, create review and editing files, avoid duplicate processing, recover interrupted work, and import results into FilmDesk. Audio separation models run inference on the supplied audio. Google user data is not used to develop, improve or train generalized AI or machine-learning models.

Where data goes

Input media is transferred from Google Drive to the owner's Kaggle runtime. Results, logs and selected checkpoints are transferred back to Google Drive and may synchronize to the owner's computer. Google and Kaggle provide the storage and computing services used by this workflow, under their respective terms and privacy policies.

The connector does not sell Google user data, use it for advertising, or send it to a separate developer-operated processing server. Data is not shared with other users by the connector; the owner controls notebook and Drive sharing settings. Optional downstream FilmDesk features using external AI services are separate from this connection and must be reviewed before the owner uses them.

Storage and retention

OAuth credentials are stored in the owner's local connection configuration and, when configured, Kaggle Secrets. Runtime configuration may exist temporarily during a session. The application should not place credentials in notebook output, processing logs, source control or public artifacts.

Input files and completed output packages remain in Drive until the owner removes them. Logs and recovery checkpoints may also persist in the configured log folder. Temporary runtime media can be cleaned up after verified upload; an interrupted runtime may retain temporary files according to Kaggle's session behavior. Revoking access does not automatically delete files already stored.

Your control and deletion

The owner can stop the notebook, remove credentials from the Mac and Kaggle Secrets, delete retained files and logs from Drive and local storage, and revoke the Google account connection. Deleting files in synchronized folders can also propagate to the computer. The owner controls this retention and deletion.

Google API data use

FilmDesk Kaggle's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including its Limited Use requirements.

This website and contact

This information site has no sign-in form, file upload or analytics script. GitHub Pages hosts it and may process ordinary request information under GitHub's privacy statement.

For privacy questions, contact the support email on the Google consent screen or open a support issue. Do not post credentials or private files. Updates to these practices will be reflected on this page.
